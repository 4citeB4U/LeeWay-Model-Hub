## Model size and compute work

The existing Formula research distinguished **stored weight bytes**, **active RAM/VRAM/KV working set**, and **execution/transfer burden**. On one quantized GGUF, generic exact compression was approximately 2.13%, not a material breakthrough; an 11.18x figure was VRAM working-set reduction, *not* lossless model compression. Do not claim mathematical Formula state summaries reconstruct original weights without exact bytes/hash and independent output tests.

For each model, original physical host must:
1. Determine separately whether the full original source bytes exist, with exact expected files, file sizes, SHA-256, licenses and provenance; record missing assets rather than inventing them. On no user device by default, but on whatever authorized host Runtime binds portably.
2. Preserve immutable original weights; baseline at least model load, tokenizer/encoder, a known-answer request, latency, tokens/sec or video frames/sec, peak CPU RAM, storage, correct output, native execution identity, and relevant thermal/energy observations.
3. Evaluate candidate representations: exact storage packaging, quantization where supported by the actual architecture/pipeline, smaller working sets, KV cache policies, optional domain-specific teacher/student distillation ONLY with approved license and evaluation data. Q4_K_M Gemma/Qwen are already quantized, so no arbitrary compression claim. Video diffusion and vision projector/text tokenizer require whole-pipeline support.
4. Measure post-transform size, peak RAM, quality regressions, end-to-end speed and integrity; reject or roll back unsuitable variants. Do not relabel OS/physical GPU compute as independent LeeWay software-GPU compute.
5. Admit a real bounded job via existing Runtime and Formula, execute through the qualified `leeway.gpu.service` software CPU/RAM backend (or separately identified approved backend), receive independent Veritas PRE/POST, actual Continuum write/readback and canonical Receipt/Learning eligibility.

**CRM/ERP — commercial follow-up.** Gemma 3 1B proposes customer messages; Gemma 270M classifies bounded records; Qwen plans business strategy. ## Three-hour governed learning cycle

This is a **requested schedule design**, not a deployed job. The existing Runtime Fabric persistent workplane, under its original authorization and the existing Machine Consciousness curriculum, should perform a bounded review every three hours when a qualified execution home is available:

1. Pull only approved and consented source examples plus verified execution outcomes; reject private, unsupported, and tampered inputs.
2. Choose one or more capability-specific teacher exercises for Office/Foundry/IDE/CRM/Logistics; capture model ID, model source/hash, request, prompt/data rights and output.
3. Grade factual correctness, regressions, cross-task transfer, latency/resources, permission boundaries, style/voice consistency and adversarial denial tests; compare to a frozen previous baseline.
4. Compile **candidate skill atoms / evaluation lessons / task procedures** using the original Machine Consciousness training path. Candidate learning cannot gain permissions.
5. Independently verify and admit only eligible outcomes to canonical Receipt Authority, Continuum and Learning Ledger. Reject duplicates, failed tests and missing Veritas.
6. No weight updates, silent fine-tuning, continuous stochastic training, new model host, or promotion without a separately reviewed model-training campaign. Missing compute means checkpoint/defer; never label a stopped host as running.

**A system that routes five specialized models and accumulates verified reusable skills can become more broadly capable**, but its combined competence is an evaluation objective, not proof that Agent Lee or a small model has inherited all knowledge and performance of every underlying model.
